# Feature audit — five selected expansions (22 Nov 2026)

Audit of the existing native Android project (`native-android/`, Kotlin 2.1, Compose, kotlinx.serialization
ProtoBuf saves) before implementing the five expansions. Baseline: commit `203f341`, `./gradlew assembleDebug
testDebugUnitTest` — APK built, 60 JVM tests passing (Robolectric for UI). No emulator or device is available in
this environment (no hardware acceleration), so device smoke tests are not possible here; the Robolectric
`ScreenshotTest` renders screens and drives a live series instead.

## Save format and migration gate

* `persist/SaveStore.kt`: one gzipped ProtoBuf `SaveFile(world, records)` per slot plus box-score pages
  (`<save>.pages/<n>.bin`), `.bak` copy on every save, export/import zip with SHA-256 manifest. `FORMAT_VERSION = 1`;
  `World.version` counts edits. There is no explicit migration step: **every model field is appended with a default**,
  so older saves decode and get defaults. `fixUp(w)` repairs older data after loading.
* Rule kept for this work: new serializable fields are appended with defaults; nothing existing is renamed or reordered.
* **Old-save fixture** (made with commit `203f341` code, before any change): `app/src/test/resources/oldsave/`
  — a T1 career 80 days in (1,836 series played, 28 trophies, 29 transfers, box-score pages).
  `MigrationTest` loads it with the current code, checks results, trophies, transfers and box scores, advances
  40 days, saves and loads again. It passes at baseline and must keep passing.

## Authoritative models / services to reuse (no parallel stores)

* Competition identity and editions: `Competition` (per season), `Season.plan`, `Progress.entrants/startDue/finish`.
* Fixtures and brackets: `Stages`, `Fixture`, `BracketNode`, `World.schedule`.
* Membership / eligibility: `Team.roster`, `Competition.registrations` + `Supporters.register/lineupFor`.
* Academy intake: `Academies`, `Career.youthIntake`, `SoloQueue.monthlyAmateurs`.
* Staff: `World.staff`, `Economy.staffOf/coachQuality`.
* Training / development: `Development.monthly/weekly`, `Scrims`.
* Match simulation: `SeriesSim` → `MobaEngine` / `TacticalEngine` / `QuickSim`; replay events `Recorder` / `ReplayCodec`.
* Rankings: `mgmt/Rankings.kt`; finance: `Economy.ledger`; persistence: `SaveStore`, `BoxStore`.

## Out of scope for this phase (per the specification)

Social media (already shipped separately; not extended here) and any database updater work (no roster refresh,
scraping, importers or image downloads). Competition-rule research is allowed and is labelled per ruleset.
